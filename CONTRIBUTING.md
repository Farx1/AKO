# Contributing

## Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu   # or a CUDA build
pip install -e ".[dev,hf]"
pre-commit install
```

## Checks (what CI runs)

```bash
pre-commit run --all-files          # ruff lint + format, codespell, yaml, whitespace
mypy                                # configured in pyproject.toml
pytest -q -m "not gpu" --cov        # CPU suite, coverage gate in pyproject.toml
pytest -q -m gpu                    # needs CUDA + Triton, not run in CI
```

## Rules

- Commits follow [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, `docs:`, `test:`, `ci:`, `bench:` ...).
- A new kernel comes with a test against its PyTorch reference, forward output
  compared with the dtype budget from `ako/validation/numerical.py`. See
  [`docs/EXTENDING.md`](docs/EXTENDING.md).
- A number added to the README must come from a JSON file committed under
  `reports/` and be regenerated by a script in `scripts/`. State the GPU, driver,
  CUDA, PyTorch, dtype and number of runs.
- Mark tests that need a GPU with `@pytest.mark.gpu` and long benchmarks with
  `@pytest.mark.slow`.
- Add a line under `## [Unreleased]` in `CHANGELOG.md`.
